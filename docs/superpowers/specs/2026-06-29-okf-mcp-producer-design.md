# okf-mcp — Producer MCP Server Design

**Date:** 2026-06-29
**Status:** Approved (brainstorming) — ready for implementation plan
**Depends on:** `okf-core` (reading, indexing, path, document APIs)

## 1. Motivation

OKF bundles are authored by *producers* — often AI agents. Today the only
programmatic surface is `okf-core`, which is deliberately **read-only**
(reading, indexing, validating). There is no supported way for an agent to
**write** a conformant concept, keep `index.md` files current, and record the
change in a `log.md`.

This spec adds a new workspace package, **`okf-mcp`**, exposing an
[MCP](https://modelcontextprotocol.io) server with producer tools that an agent
can call to author and maintain a bundle. Each write keeps the bundle's derived
artifacts (indexes, logs) in sync automatically.

### Goals

- A new `packages/okf-mcp` member with an MCP server built on the official
  `mcp` Python SDK (FastMCP), depending on `okf-core`.
- Write tools: **`add`** (create a concept) and **`patch`** (update one).
- Read tools: **`get`** (one concept), **`list`** (enumerate concepts), and
  **`read_index`** (progressive disclosure — read `index.md` files).
- After every write: regenerate indexes and append a directory-scoped log entry.
- Keep authoring/writing logic out of `okf-core`, which stays read-only.

### Non-goals

- No bundle-wide conformance validation inside the tools (re-index only). The
  separate `validate_bundle` / `python -m okf_core.validate` remains the way to
  check conformance.
- No delete/move/rename tools in this iteration.
- No frontmatter-key deletion via `patch` (merge-only; see §5.2).
- No remote/HTTP transport configuration beyond the SDK default (stdio).

## 2. Architecture

Approach **A — thin server over a testable operations module**:

```
packages/okf-mcp/
├── pyproject.toml            # name=okf-mcp; deps: mcp, okf-core (workspace)
├── README.md
├── src/okf_mcp/
│   ├── __init__.py           # version + public re-exports
│   ├── operations.py         # framework-agnostic add/patch/get/list + log/root helpers
│   └── server.py             # FastMCP app; thin tool wrappers; main()
└── tests/
    ├── test_operations.py    # unit tests over tmp_path bundles (primary coverage)
    └── test_server.py        # light smoke: tools registered / callable
```

- **`operations.py`** contains pure functions that take an explicit
  `bundle_root: Path` and do all the work (validation, file I/O, log, reindex).
  They have no dependency on the MCP runtime and are unit-tested directly.
- **`server.py`** constructs `FastMCP("okf-producer")`, resolves the bundle
  root, and maps each `@mcp.tool()` to the matching `operations` function. It
  contains no business logic. `main()` calls `mcp.run()` (stdio transport).

The uv workspace (`members = ["packages/*"]`) picks up `okf-mcp` automatically;
`uv sync` installs it editable alongside `okf-core`.

## 3. Bundle root resolution

Every operation needs a bundle root, resolved in this order:

1. The `bundle_root` argument, if provided to the tool.
2. Otherwise the `OKF_BUNDLE_ROOT` environment variable.

Environment loading uses **`pydantic-settings`**: a `Settings`
(`BaseSettings`) model in `server.py` declares `okf_bundle_root: Path | None`
bound to the `OKF_BUNDLE_ROOT` env var (e.g. `model_config =
SettingsConfigDict(env_prefix="OKF_")`). The server reads it once at startup;
the resolver falls back to it when a tool call omits `bundle_root`.

If neither yields a value, or the resolved path is not an existing directory,
raise `ValueError` with a clear message. The path is resolved with
`Path(...).resolve()` before use.

The expected deployment is one server per bundle (the MCP client config sets
`OKF_BUNDLE_ROOT`); the per-call override exists for multi-bundle or ad-hoc use.

## 4. Frontmatter keys

`add`/`patch` take frontmatter as a **single generic dict** (the agent's chosen
shape). The tool *descriptions* document the recommended OKF keys so the agent
authors conformant docs without the schema constraining it:

| Key | Meaning |
|-----|---------|
| `type` | **Required.** Non-empty string naming the kind of concept (e.g. `BigQuery Table`, `Metric`). Enforced by `add` (FM-01). |
| `title` | Human-readable display name. Used for the log link label and index entries. |
| `description` | One-sentence summary. Used in `index.md` entries. |
| `resource` | Canonical URI of the underlying asset (when bound to one). |
| `tags` | YAML list of short strings. |
| `timestamp` | ISO 8601 datetime of the last change. **Auto-managed** (see §5.3) unless the caller sets it. |

Any other producer-defined key is preserved verbatim on round-trip. (Note:
`okf_version` belongs only in the bundle-root `index.md`, which these tools do
not touch — index files are generated by `regenerate_indexes`.)

## 5. Tools

All concept identifiers are **concept IDs** — the bundle-relative path with no
`.md` suffix (e.g. `tables/orders`). IDs are validated with
`okf_core.parse_concept_id`; additionally, a final segment of `index` or `log`
is rejected (would collide with reserved files — RSV-01).

### 5.1 `add` — create a concept

**Parameters**

- `concept_id: str` — e.g. `tables/orders`.
- `frontmatter: dict` — must contain a non-empty string `type`.
- `body: str` — free-form markdown body (may be empty).
- `bundle_root: str | None = None` — override.

**Behavior**

1. Resolve bundle root (§3); validate `concept_id` (§5).
2. Compute the file path with `okf_core.concept_id_to_path`.
3. **Error if the file already exists** (`add` never clobbers).
4. Enforce non-empty string `type` in `frontmatter` (FM-01) — else `ValueError`.
5. Apply auto-timestamp (§5.3).
6. Create parent directories; write `OKFDocument(frontmatter, body).serialize()`.
7. Append a **Creation** log entry to the concept's directory log (§5.4).
8. `okf_core.regenerate_indexes(bundle_root)`.
9. Return the result summary (§6).

### 5.2 `patch` — update a concept

**Parameters**

- `concept_id: str`.
- `frontmatter: dict | None = None` — keys to merge. Only keys whose value is
  **not `None`** are applied; unlisted/None keys are left untouched.
  **No deletion** — clearing a key is out of scope ("only update keys assigned
  values").
- `body: str | None = None` — replaces the body only when provided (non-`None`);
  omitting it keeps the existing body.
- `bundle_root: str | None = None` — override.

**Behavior**

1. Resolve bundle root; validate `concept_id`.
2. Compute the path; **error if it does not exist**.
3. Parse the current file with `OKFDocument.parse`.
4. Merge frontmatter (non-`None` values overwrite/extend, preserving existing
   key order; new keys appended). Replace body if `body` was provided.
5. Apply auto-timestamp (§5.3).
6. Write the serialized document back.
7. Append an **Update** log entry to the concept's directory log (§5.4).
8. `regenerate_indexes(bundle_root)`.
9. Return the result summary (§6).

### 5.3 Auto-timestamp

`timestamp` is set to the current UTC time in ISO 8601 with a `Z` suffix (e.g.
`2026-06-29T12:34:56Z`, seconds precision):

- **`add`:** set it iff the caller did not include `timestamp` in `frontmatter`.
- **`patch`:** refresh it to now unless the caller explicitly passed a
  `timestamp` in `frontmatter` (a patch is a meaningful change).

### 5.4 Log appending

Target file: `log.md` **in the changed concept's own directory** (the root
`log.md` when the concept sits at the bundle root). Created if absent.

- **Link form:** relative to that directory — `[<label>](<name>.md)`, where
  `<label>` is the concept's `title` if present, else its last id segment.
- **Entry:** `* **Creation**: Added [<label>](<name>.md).` for `add`;
  `* **Update**: Updated [<label>](<name>.md).` for `patch`.
- **Date grouping (newest-first, ISO `YYYY-MM-DD` — LOG-01/LOG-02):**
  - New file → `# Update Log\n\n## <today>\n<entry>\n`.
  - Existing file whose first `## ` date group is today → prepend the entry as
    the first bullet under that group.
  - Otherwise → insert a new `## <today>` group at the top, after an optional
    leading `# …` title line, above the previous newest group.

### 5.5 `get` — read one concept

**Parameters:** `concept_id: str`, `bundle_root: str | None = None`.

Reads the single file (no full-bundle load), returns:
`{ "id", "frontmatter", "body", "links_to" }`, where `links_to` is computed with
`okf_core.extract_links`. Error if the file does not exist.

### 5.6 `list` — enumerate concepts

**Parameters:** `type: str | None = None`, `prefix: str | None = None`,
`bundle_root: str | None = None`.

Loads the bundle with `okf_core.Bundle.load`, returns a list of
`{ "id", "type", "title", "description", "tags" }`, optionally filtered by exact
`type` and/or id `prefix` (e.g. `tables/`). `index.md`/`log.md` are excluded by
`Bundle.load` already.

### 5.7 `read_index` — progressive disclosure

**Parameters**

- `dir: str | None = None` — bundle-relative directory (e.g. `tables`); the
  bundle root when omitted.
- `depth: int = 1` — how many directory levels of indexes to include; an
  integer in **1–3** (else `ValueError`).
- `bundle_root: str | None = None` — override.

**Behavior**

Resolve the target directory under the bundle root (must stay within it).
Collect `index.md` files breadth-first starting at `dir`: level 1 is
`<dir>/index.md`; each further level descends into on-disk subdirectories that
contain an `index.md`, up to `depth`. Missing `index.md` files are skipped —
this tool is read-only and never regenerates.

**Returns** a depth-ordered (breadth-first) list of
`{ "dir", "path", "content" }`, where `dir` is bundle-relative (`""` for the
root), `path` is `<dir>/index.md` (bundle-relative), and `content` is the raw
`index.md` markdown. The list is empty when no index exists at/under `dir`
within `depth`.

## 6. Return values

Write tools return a structured summary (serialized to text by FastMCP):

```json
{
  "concept_id": "tables/orders",
  "path": "tables/orders.md",
  "action": "created",          // or "updated"
  "log": "tables/log.md",
  "indexes": ["index.md", "tables/index.md"]
}
```

Paths are bundle-relative. Read tools return the shapes in §5.5 / §5.6 / §5.7.

## 7. Error handling

Preconditions raise `ValueError` with actionable messages; FastMCP surfaces them
to the client as tool errors:

- bundle root unresolved or not a directory;
- `concept_id` invalid or a reserved final segment (`index`/`log`);
- `add` target already exists;
- `patch`/`get` target does not exist;
- `add` frontmatter missing a non-empty string `type`.

I/O and YAML errors propagate as-is (already `OKFDocumentError`/`OSError`).

## 8. Testing (TDD)

Primary coverage is unit tests on `operations` against `tmp_path` bundles:

- `add`: happy path writes file + frontmatter + body; rejects existing path;
  rejects missing/empty `type`; rejects reserved/invalid `concept_id`; sets
  `timestamp` when omitted and preserves a caller-supplied one.
- `patch`: merges only non-`None` keys; preserves unlisted keys and key order;
  replaces body only when provided; refreshes `timestamp`; errors when missing.
- log: creates a new `log.md`; prepends under an existing today group; inserts a
  new dated group above older ones; uses the directory-relative link + title
  label; root-level concept logs to the root `log.md`.
- index: indexes are regenerated after add/patch (assert an expected `index.md`
  exists/updates).
- `get` / `list`: shapes and filters; not-found error for `get`.
- `read_index`: depth=1 returns the single directory index; depth=2/3 descend
  breadth-first; out-of-range `depth` errors; missing index → skipped/empty;
  a `dir` escaping the bundle root is rejected.

`test_server.py` is a light smoke test that the FastMCP app registers the five
tools and a basic call round-trips (in-memory if the SDK supports it; otherwise
assert tool registration only). Run with the workspace `uv run pytest`.

## 10. Out of scope / future

- Delete/move/rename tools; frontmatter-key deletion in `patch`.
- Bundle-wide conformance validation surfaced from the tools.
- HTTP/SSE transport and auth.
- Backlinks in `get` (cheap to add later via `Bundle.backlinks`).
